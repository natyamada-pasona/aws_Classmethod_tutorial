# 02: API-Driven Development and Synchronous Event Sources

The Lambda `invoke` command is used to directly call a Lambda function from the AWS CLI.

```cmd
# Synchronous invocation (default) - waits for a response
aws lambda invoke --function-name my-function \
  --invocation-type RequestResponse \
  response_output.json

# Asynchronous invocation - does not wait for a response
aws lambda invoke --function-name my-function \
  --invocation-type Event \
  response_output.json

```


## Choosing Endpoints Based on Access Patterns

API Gateway offers three endpoint types. Choose based on "who accesses the API and from where."

- Edge-Optimized: For global access. Routes through CloudFront edge locations (cache points around the world) to reduce latency. This is the default.
- Regional: For access primarily from within the same region.
- Private: For access only from within a VPC.

This allows you to optimize latency and cost.



## Differences Between HTTP API and REST API
These are different from the general concept of RESTful APIs. "HTTP API" and "REST API" refer to specific AWS service names.

| | HTTP API | REST API |
|---|---|---|
| Cost | Low (~$1.00 per million requests) | High (~$3.50 per million requests) |
| Latency | Low | Higher than HTTP API |
| Authentication | JWT, OIDC | JWT, OIDC, IAM, Cognito, API Keys |
| Endpoints | Regional only | Edge-Optimized, Regional, Private |
| When to choose | Good as the default choice | When HTTP API lacks required features |

### Federated Identity

A two-stage mechanism: "Authenticate with Cognito User Pool → Convert to temporary IAM credentials via Federated Identity → Authorize with IAM policies."

#### Flow

1. Client authenticates with Cognito User Pool
2. Obtains a JWT (ID token) from the User Pool
3. Uses the JWT to request temporary AWS credentials from Cognito Federated Identity
4. Federated Identity validates the ID token
5. Issues temporary IAM credentials (access key, secret key, session token)
6. Client signs the payload with those credentials (SigV4 signature)
7. Calls API Gateway with the signed request
8. API Gateway queries IAM to verify the IAM policy associated with the temporary credentials
9. If authorized, invokes the Lambda function
10. Lambda accesses AWS resources such as DynamoDB

#### Benefits

- No need to store long-term AWS credentials on the client (temporary credentials expire)
- Fine-grained access control via IAM policies (per API path, method, etc.)
- Separation of authentication (User Pool) and authorization (IAM)

Key point: The role of Federated Identity is to convert a JWT ("who is this person") into temporary IAM credentials ("what can this person do").

1. Is it correct to understand distributed services as roughly equivalent to microservices?
Distributed services are a mechanism for splitting processing across multiple servers. They are not necessarily microservices.
Separating a system into a web server, application server, and DB server is also considered a distributed service.

2. In event-driven development, how do you verify eventual consistency on the producer side? For example, if the producer never finishes processing or silently fails.
You don't verify completion in real time. Instead, you handle it through retries on failure, checking dead-letter queues, and reviewing logs. The practice of "reviewing logs" ties into the concept of observability.

1. When implementing APIs with Lambda, a single service could require dozens or even hundreds of APIs.
From an operational perspective, how are these typically managed? Is the idea to use AWS SAM?

Yes, as you mentioned, managing them from the console becomes difficult as the number grows, so using SAM for management is a good approach.
